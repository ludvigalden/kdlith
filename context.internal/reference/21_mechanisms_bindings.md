## Conditional occurrence bounds, in detail

A `when property=FIELD equals=V` leaf compares one property with one
value; `when-all` (every member matches) and `when-any` (at least
one) compose leaves and nest to any depth. There is no negation, no
ordering, and no other predicate. Only a branch root carries
`min-occurs` / `max-occurs` (`KDLITH-BND005` on a nested member).
The gating property must be a declared scalar or enum field,
optionally `optional` (`KDLITH-SCH016`; references, objects, lists,
maps, and codec-bound types never gate), and `equals` must decode as
that type (`KDLITH-DLC005`). An absent property matches no leaf;
`equals=#null` matches only an explicitly held `#null`. Branches are
tried in declaration order, first match winning, and a matching
branch replaces both of the rule's bounds (a bound it does not spell
takes its default). A rule with branches must spell at least one
bound of its own (`KDLITH-SCH019`). Two branches of one rule must be
provably never-matching on the same node (`KDLITH-SCH017`): a leaf
is required when every combinator between it and its branch root is
a `when-all`, and two branches are disjoint when each carries a
required leaf on one shared property with distinct values; the check
is conservative. A `children-group` rule's branches are copied into
every member rule it expands to. Cases select a node's type when it
opens; conditions select its bounds when its scope completes, and
conditions never re-admit a child the selected type does not declare
(`KDLITH-BND014`). Evaluation happens per node instance at scope
completion against the node's final values; a count outside the
selected bounds is `KDLITH-BND002` — conditions add no run-time
diagnostic code.

## Compact child-term spelling, in detail

`compact=#true` on a `child` or `children` source admits the property
spelling `NAME=VALUE`, which binds on its own as one `NAME` child
carrying the property's value as argument 0, opened and closed at the
property's position — before the node's block children, in property
order, meeting union dispatch, occurrence bounds, and duplicate
detection exactly as the child would. Several properties are several
sibling children, never an implicit wrapper. A property cannot repeat
a name (`KDLITH-SYN003`, checked before the splice), so a compact
source admits at most one term per child name; repeating a name takes
the block form. The bound item stream is
the block spelling's; only the `origins` view tells the spellings
apart, since a literal's origin is the property's span. A child
admits the spelling only when its one argument fills everything it
binds: a scalar child; a child whose nested sources are all
`argument 0`; or a declared node binding at least one field, every
field from `argument 0` alone, with no role, `value` block, cases,
`otherwise`, children or group rules, descendants, sequence, or
effects. A compact source on a non-qualifying child is
`KDLITH-DLC005`; a property spelling a non-compact child is
`KDLITH-BND005`; a value the child's type rejects fails as the
child's argument would (`KDLITH-BND003`). The binder performs the
splice on every reading path, and a compact source changes the
definition's canonical-summary digest.

## Node declaration metadata, in detail

`annotation NAME TYPE [required]` at the schema root declares
vocabulary: `NAME` kebab-case (`AnnotationName`), `TYPE` a scalar
(built-in scalar or declared `string`/`enum`); every other type
spelling is rejected at compile (`KDLITH-DLC005`, unknown name
`KDLITH-SCH001`). Facts are `annotation NAME VALUE` children with any
single KDL scalar; the compiler checks declared names, one carrying
per node, values decoding as the declared type, and every node
carrying each required annotation (all `KDLITH-DLC005`, skipped
under `--scope local`). A generated schema crate exposes one public
constant per fact (`<NODE>_<ANNOTATION>`, ordinal suffixes for
same-stem collisions); `description=` is metadata the `effective`
view shows, and both description and annotations join the digest the
canonical summary is taken over, so two definitions differing in
metadata are different definitions.
