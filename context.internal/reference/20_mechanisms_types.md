# In-scope mechanisms: logical types

Declared by `pkg/kdl/schemas/dialect/types.kdl`.

| Mechanism                            | What the dialect declares                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Draft        |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| Logical types separate from bindings | Types say what a field is; bindings say how it is spelled. A logical field is never inherently "argument 0" or "a child named x".                                                                                                                                                                                                                                                                                                                                                                                                                                                            | R1 §2, R2 §3 |
| Type declarations                    | `string`, `enum`, `object`, `union`, `map`, `codec`, and `asset` declarations (the `TypeDef` union), each inside a `types` container                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | R1 §2, R2 §2 |
| Type expressions                     | A type-description grammar inside a quoted string, checked by the registered validator `type-expression` version `0`; not an expression evaluator                                                                                                                                                                                                                                                                                                                                                                                                                                            | R2 §2        |
| Type constructors                    | `optional`, `nullable`, `list`, `map`, `ordered-map`, `union`, `ref`. Fields are required unless optional; absence, null, and an empty list are distinct states                                                                                                                                                                                                                                                                                                                                                                                                                              | R2 §2, R3 §4 |
| Generic type declarations            | A type declaration or codec may declare type parameters as `parameter T` children. A type expression instantiates a generic with `T<A, B>`; the compiler substitutes arguments for parameters when the definition compiles, so no generic survives into a compiled plan. Arity is checked at compile time, and an instantiation cycle — other than through `ref<T>`, which stays symbolic — is `KDLITH-SCH009`                                                                                                                                                                               | R2 §2, R2 §5 |
| Ordered keyed collections            | `ordered-map<K, V>`: unique keys, declaration order retained                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | R3 §4        |
| Built-in scalars                     | `String`, `Bool`, `Integer`, `Decimal`, `U64`, and `ValueExpr` (any single KDL scalar, checked against the type of the field holding it)                                                                                                                                                                                                                                                                                                                                                                                                                                                     | R2 §2, R2 §7 |
| Patterned strings                    | `string` types with `pattern` (whole-string match), `min-length`, a built-in `format` (`kebab-case`, `camel-case`, `lower-snake`, `upper-snake`, `uuid`, `zero-padded` with `width`), or a registered `validator` with a version                                                                                                                                                                                                                                                                                                                                                             | R2 §2        |
| Pattern codecs                       | `codec NAME output=TYPE` inside `types`: a `match` child carries one regular expression that must match the whole string, `capture NAME TYPE` children type each named group, and the capture set must cover the match's named groups exactly. An optional `namespace NAME` records the reference namespace a decoded identity belongs to. A codec name is usable wherever a type expression names a declared type; the decoded value's logical type is `output=`, and at bind time a matching string decodes through the codec in the stream while provenance retains the original spelling | R2 §4, R2 §9 |
| Enum member metadata                 | Member descriptions remain metadata after compilation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | R2 §7        |
| Discriminated unions                 | A union variant is selected by the node name that spells it; no speculative parsing or backtracking                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | R1 §3        |
| Union dispatch by value prefix       | A variant may carry `prefix="…"`: for a union bound from a scalar value, the variant is selected when the value's text starts with the prefix. Prefixes of one union are checked pairwise at compile time (`KDLITH-SCH010`); once a prefix selects a variant, a failure inside it is an error, never a fallback. A scalar no prefix selects binds as the first un-prefixed variant, in declaration order, whose type accepts it. The scalar-kind fallback is a deliberate departure from prefix-only dispatch, so a union can hold either a literal number or a prefixed template            | R2 §4        |
| Maps                                 | `map` declarations with `key-type` and `value-type` children                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | R1 §2        |
| Asset types | `asset NAME` inside `types` with `kind` (`file`/`dir`), `extensions`, `base` (`document`/`source`), `patterns`, and `digest` children: a field whose value is a location naming a non-KDL file or directory, resolved and confined like an import location, checked for existence, kind, and extension (`KDLITH-LOC008`), and never read beyond its digest | R1 §5 |
| Documented default versus fallback   | `documented-default` is metadata only and never materializes an absent value; `fallback` supplies an absent value                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | R2 §10       |
| Field sensitivity                    | A logical field may carry `sensitivity=secret` or `sensitivity=reference`: `secret` marks a resolved sensitive value, `reference` an identifier that locates one; a type modeling both keeps them as separate fields. Metadata is not enforcement: every serialization and diagnostic surface applies an explicit output policy — emit, omit, or redact — and a `secret` field is never emitted unless the policy explicitly says emit                                                                                                                                                       | R3 §8        |
| Object constraints                   | `all-or-none`, `requires`, `bound`, `at-most-one`, and `exactly-one-field`: enforceable policies an author states explicitly, never rules extracted from descriptions. The binder enforces them on every type a node binds as (`KDLITH-BND011`; a number outside a `bound` is `KDLITH-BND012`; a broken exclusivity list is `KDLITH-BND013`); `#null` and an empty collection are supplied values, only a field holding none is absent                                                                                                                                                       | R2 §10       |
